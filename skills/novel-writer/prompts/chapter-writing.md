# 章节编写提示模板

## 目标

根据分卷大纲编写章节正文，内置质量检查。

## 前置条件

- 项目已初始化
- 分卷大纲已完成（`volumes/vol-{n}.json` 存在）
- 目标章节的状态为 `planned`

## 执行步骤

### 1. 加载上下文

#### 必须加载
- `meta.json`（用户偏好）
- `progress.json`（当前进度）
- `index.json`（全局索引）
- `world.json`（世界观设定）
- `characters.json`（人物设定）
- `factions.json`（势力设定）
- 目标章节的规划（`volumes/vol-{n}.json` 中的章节信息）

#### 按需加载
- 前一章全文（保持连贯性）
- 涉及伏笔的相关章节
- 涉及人物首次出场的章节
- 与本章地点/事件相关的历史章节

### 2. 编写章节正文

#### 开场
- 快速建立场景（时间、地点、氛围）
- 避免长篇景物描写
- 用动作或对话开场优于纯描写

#### 场景展开
- 每个场景有明确的冲突
- 场景必须有转折（因此/但是）
- 对话符合人物说话风格
- 描写服务于情节或情感

#### 章末
- 章末钩子或转折
- 给读者继续阅读的理由
- 避免在平淡处结束

### 3. 内置质量检查

编写完成后，自动检查以下项目：

#### 推进性检查
- [ ] 本章是否有新的信息增量
- [ ] 本章是否推动了情节或人物关系
- [ ] 每个场景是否有明确功能
- [ ] 场景功能是否与前后章节重复

#### 注水检查
- [ ] 是否有无意义的景物描写堆砌
- [ ] 是否有重复已述信息
- [ ] 是否有空洞的内心独白
- [ ] 字数是否来自情节密度而非填充

#### AI 味检查
- [ ] 是否使用了禁用词汇
- [ ] 是否有三段式排比过度使用
- [ ] 是否有破折号滥用
- [ ] 是否有模糊归因
- [ ] 句子长度是否有变化
- [ ] 结尾是否刻意升华

#### 一致性检查
- [ ] 人物行为是否符合性格设定
- [ ] 世界观规则是否被遵守
- [ ] 时间线是否连贯
- [ ] 人物关系是否与已有设定一致
- [ ] 势力关系是否正确

#### 视角检查
- [ ] 每个场景是否有明确的 POV 人物
- [ ] 是否写入了 POV 人物不可能知道的信息
- [ ] 是否直接写入了其他人物的内心想法
- [ ] 是否有上帝视角式的预知或总结
- [ ] 同一场景内是否保持了视角一致

#### 伏笔检查
- [ ] 是否埋设了新伏笔（如有需要）
- [ ] 是否回收了已有伏笔（如有需要）
- [ ] 伏笔的处理是否自然

### 4. 更新记忆系统

#### 更新章节数据
保存到 `chapters/ch-{n}.json`：
- 章节正文
- 字数统计
- 场景摘要
- 关键事件
- 质量评估笔记
- 状态设为 `final`

#### 更新伏笔
- 新增伏笔添加到 `foreshadowing.json`
- 已回收伏笔移到 `foreshadowing-history.json`

#### 更新时间线
- 本章事件添加到 `timeline.json`

#### 更新人物关系
- 关系变化更新到 `relationships.json`
- 变更记录添加到 `relationships-history.json`

#### 更新索引
- 更新 `index.json` 中的章节摘要和状态

#### 更新进度
- 更新 `progress.json` 中的 `total_chapters_written`、`total_word_count`、`last_written_at`

#### 记录变更
- 记录到 `history.json`

### 5. 输出章节

向用户展示：
- 章节正文
- 字数统计
- 质量评估摘要
- 伏笔变动（新增/回收）
- 人物关系变化

### 6. 询问下一步

- 是否继续下一章
- 是否需要修改本章
- 是否有其他指示

## 注意事项

- 严格遵循质量铁律
- 对话必须有辨识度，不能所有角色说话一个味
- 描写要有选择性，聚焦关键细节
- 内心活动要推动决策，不能是空洞的感慨
- 章末钩子要自然融入情节
- 如果本章涉及重要转折，确保有足够的铺垫
