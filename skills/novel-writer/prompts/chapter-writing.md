# 章节编写提示模板

## 目标

根据分卷细纲编写章节正文，内置质量检查。

## 前置条件

- 项目已初始化
- 分卷细纲已完成（`volumes/vol-{n}.json` 存在）
- 目标章节的状态为 `planned`

## 执行步骤

### 1. 加载上下文

#### 必须加载
- `meta.json`（用户偏好）
- `progress.json`（当前进度）
- `index.json`（全局索引）
- `world.json`（世界观设定）
- `characters.json`（人物设定）
- `factions.json`（势力设定）
- 目标章节的规划（`volumes/vol-{n}.json` 中的章节信息）

#### 按需加载
- 前一章全文（保持连贯性）
- 涉及伏笔的相关章节
- 涉及人物首次出场的章节
- 与本章地点/事件相关的历史章节

### 2. 编写章节正文

#### 开场
- 快速建立场景（时间、地点、氛围）
- 避免长篇景物描写
- 用动作或对话开场优于纯描写

#### 场景展开
- 每个场景有明确的冲突
- 场景必须有转折（因此/但是）
- 对话符合人物说话风格
- 描写服务于情节或情感

#### 章末
- 章末钩子或转折
- 给读者继续阅读的理由
- 避免在平淡处结束

### 3. 内置质量检查

编写完成后，**必须逐项检查**以下所有维度。任何一项不通过都必须修改。

#### 3.1 推进性检查（必须通过）
- [ ] 每段有信息增量或情感推进
- [ ] 每个场景有明确功能（推进/揭示/转折/氛围）
- [ ] 连续场景功能不重复
- [ ] 本章有"因此"或"但是"逻辑推进
- [ ] 章末有钩子或转折

#### 3.2 注水检查（必须通过）
- [ ] 无无意义的景物描写堆砌
- [ ] 无重复已述信息（除非有叙事目的）
- [ ] 无空洞的内心独白
- [ ] 字数来自情节密度而非填充

#### 3.3 AI 味检查（必须通过）
- [ ] 零禁用词（此外、至关重要、深入探讨、格局、织锦等）
- [ ] 无三段式排比过度使用
- [ ] 无破折号滥用
- [ ] 无模糊归因
- [ ] 句子长度有变化
- [ ] 对话有辨识度

#### 3.4 视角检查（必须通过）
- [ ] 每场景有且只有一个 POV 人物
- [ ] 未写入 POV 人物不可能知道的信息
- [ ] 未直接写入其他人物的内心想法
- [ ] 无上帝视角预知

#### 3.5 一致性检查（必须通过）
- [ ] 人物行为符合性格和目标
- [ ] 世界观规则被遵守
- [ ] 时间线连贯
- [ ] 人物关系与设定一致
- [ ] 势力关系正确

#### 3.6 伏笔检查（如有需要）
- [ ] 已埋伏笔被适时回收
- [ ] 新伏笔被记录
- [ ] 伏笔处理自然

#### 3.7 质量评分

| 维度 | 优秀 (9-10) | 良好 (5-6) | 差 (1-2) |
|------|-------------|------------|----------|
| 推进性 | 每段有信息增量 | 有推进但有明显填充 | 几乎无推进 |
| AI味 | 零禁用词 | 禁用词 3-5 次 | 典型 AI 风格 |
| 视角 | 严格一致 | 明显错误 | 混乱 |
| 节奏 | 张弛有度 | 单一 | 混乱 |
| 对话 | 有辨识度 | 区分度不够 | 一个味 |
| 一致性 | 完全一致 | 可察觉矛盾 | 设定混乱 |

**判定规则**：
- 任何一项为"差"→必须修改
- 3 项以上为"良好"→建议修改
- 全部"良好"以上→可接受

### 4. 更新记忆系统

#### 更新章节数据
保存到 `chapters/ch-{n}.json`：
- 章节正文
- 字数统计
- 场景摘要
- 关键事件
- 质量评估笔记
- 状态设为 `final`

#### 更新伏笔
- 新增伏笔添加到 `foreshadowing.json`
- 已回收伏笔移到 `foreshadowing-history.json`

#### 更新时间线
- 本章事件添加到 `timeline.json`

#### 更新人物关系
- 关系变化更新到 `relationships.json`
- 变更记录添加到 `relationships-history.json`

#### 更新索引
- 更新 `index.json` 中的章节摘要和状态

#### 更新进度
- 更新 `progress.json` 中的 `total_chapters_written`、`total_word_count`、`last_written_at`

#### 记录变更
- 记录到 `history.json`

### 5. 输出章节

向用户展示：
- 章节正文
- 字数统计
- 质量评估摘要
- 伏笔变动（新增/回收）
- 人物关系变化

### 6. 询问下一步

- 是否继续下一章
- 是否需要修改本章
- 是否有其他指示

## 注意事项

- 严格遵循质量铁律
- 对话必须有辨识度，不能所有角色说话一个味
- 描写要有选择性，聚焦关键细节
- 内心活动要推动决策，不能是空洞的感慨
- 章末钩子要自然融入情节
- 如果本章涉及重要转折，确保有足够的铺垫
