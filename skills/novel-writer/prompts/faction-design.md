# 势力设计提示模板

## 目标

设计小说中的势力/阵营/组织，构建冲突框架。

## 前置条件

- 项目已初始化
- 可选：已有世界观或人物设定（非必须）

## 执行步骤

### 1. 确定势力范围

根据题材和用户需求，确定需要设计的势力：
- **主要势力**（2-4 个，构成核心冲突）
- **次要势力**（按需，丰富世界）
- **隐藏势力**（可选，用于后期反转）

如果已有世界观，确保势力与世界设定兼容。
如果已有人物，将人物分配到对应势力中。

### 2. 生成势力设定

每个势力包含以下信息：

#### 基本信息
- 势力名称
- 势力类型（宗门、帝国、组织、家族、学派等）
- 简要描述（100-200 字）

#### 目标与动机
- 核心目标（势力追求什么）
- 内在动机（为什么追求这个目标）
- 短期目标 vs 长期目标

#### 实力评估
- 实力等级（1-10）
- 影响区域
- 核心资源/优势
- 弱点/短板

#### 人员构成
- 关键成员（关联到 characters.json 中的人物 ID）
- 领导结构
- 内部派系（如有）

#### 外交关系
- 盟友势力
- 敌对势力
- 中立/摇摆势力
- 关系原因

#### 内部矛盾
- 内部冲突点（理念分歧、权力斗争等）
- 潜在分裂风险

### 3. 主动检查

生成后主动检查：
- 势力目标是否与人物目标产生冲突或协同
- 势力之间的关系是否构成足够的戏剧张力
- 实力评估是否合理（避免一边倒）
- 内部矛盾是否能为情节提供素材
- 如果已有世界观：势力分布是否与地理/历史设定兼容

### 4. 提出优化建议

- 势力是否过于脸谱化（纯善/纯恶）
- 是否有足够的灰色地带供人物活动
- 势力冲突是否有多层次（不仅是武力对抗）
- 是否有被忽略的潜在冲突点

### 5. 等待用户确认

展示所有势力设定，询问用户：
- 是否需要增删势力
- 需要调整哪些势力
- 是否有补充设定

### 6. 保存设定

用户确认后，更新 `factions.json`，记录变更到 `history.json`。

## 输出格式

势力设定以结构化 JSON 格式保存到 `factions.json`，同时向用户展示可读版本。

## 注意事项

- 势力不能只是背景板，要能主动推动情节
- 每个势力内部应该有分歧，不是铁板一块
- 势力之间的关系应该是动态的，可以随情节变化
- 隐藏势力要有合理的铺垫线索，不能凭空出现
- 如果从势力开始设计，标注需要后续补充的人物和世界观要素
