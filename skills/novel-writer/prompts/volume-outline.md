# 分卷细纲提示模板

## 目标

根据总大纲划分卷次，为每一卷和每一章制定详细规划。

**重要原则**：分卷细纲必须与总大纲严格对齐，确保剧情不超出全书大纲设定的范围。

## 前置条件

- 项目已初始化
- 总大纲已完成（`outline.json` 存在）

## 执行步骤

### 1. 划分卷次

根据总大纲的节拍和情节密度，将故事划分为若干卷：

每卷包含：
- **卷号**
- **卷名**
- **卷概述**（本卷的核心事件和弧线）
- **章节范围**（从第几章到第几章）
- **本卷弧线**（本卷中主角的成长/变化）
- **本卷主题**（本卷侧重探讨的主题侧面）

### 2. 对齐全书大纲

**核心约束**：本卷的剧情内容必须严格对应总大纲中该卷设定的情节范围。

- 提取总大纲中该卷的所有剧情事件（main plot beats）
- 确保分卷细纲中的每一章都服务于这些剧情事件
- **禁止提前出现下一卷的情节**
- 如果需要增加日常/过渡内容，从总大纲的支线中选取，不能自行创造新情节

### 3. 篇幅规划

#### 估算章节数

根据该卷的剧情内容估算所需章节数：
- 核心事件（主线剧情）分配较多章节
- 日常/过渡内容分配较少章节
- 建议比例：**核心事件 70%，日常/过渡 30%**

#### 安排剧情节奏

- 核心事件之间插入日常事件调节节奏
- 遵循"张弛有度"原则：
  - 连续紧张剧情后必须有舒缓章节
  - 连续日常后必须有高密度章节
- 不能连续 3 章以上都是日常内容

#### 多女主/多线轮换（如适用）

如果小说是多女主或多人视角类型：
- 确保每位女主的剧情在每 **5-10 章**内至少出现一次
- 不能连续 10 章以上只讲述一个女主的剧情
- 安排其他角色合理交替出场
- 各自剧情线要交替推进，不能一条线写到尾再开另一条

### 4. 规划每章

每章包含以下信息：

#### 基本信息
- 章号
- 章名
- 所属卷
- POV 人物（视角人物）
- 时间
- 地点

#### 内容规划
- 章概述（100-200 字）
- 情节点（beats，2-4 个）
  - 每个情节点的描述
  - 功能（推进/揭示/转折/铺垫）
  - 涉及人物
- 本章冲突
- 本章结果
- 章末钩子

#### 技术要求
- 目标字数
- 场景数量（2-4 个场景）
- 场景规划（每个场景的地点、冲突、转折）

### 5. 全局检查

生成后主动检查：

**一致性检查**：
- [ ] 本卷剧情是否在总大纲设定的范围内
- [ ] 是否有提前出现下一卷的情节
- [ ] 章节之间是否有因果联系（非堆砌）

**篇幅检查**：
- [ ] 核心事件与日常内容的比例是否合理
- [ ] 是否有连续 3 章以上的纯日常内容
- [ ] 节奏是否张弛有度

**多线检查**（如适用）：
- [ ] 每位女主的剧情是否在每 10 章内出现过
- [ ] 是否有连续 10 章以上只讲一个女主
- [ ] 多线是否交替推进

**质量检查**：
- [ ] 每章是否有明确的功能（非填充章节）
- [ ] 转折分布是否均匀
- [ ] 伏笔的埋设和回收是否跨章合理
- [ ] POV 分配是否合理
- [ ] 章末钩子是否足够吸引人

### 6. 提出优化建议

- 是否有超出总大纲范围的剧情
- 是否有功能重复的章节
- 是否有章节信息量过低
- 多线轮换是否合理
- 卷与卷之间是否有清晰的弧线

### 7. 等待用户确认

展示分卷细纲，询问用户：
- 卷次划分是否合理
- 章节规划是否需要调整
- 多线轮换是否满意
- 是否有补充或删减

### 8. 保存分卷细纲

用户确认后：
- 每卷保存到 `volumes/vol-{n}.json`
- 更新 `index.json` 中的章节索引
- 更新 `progress.json` 中的 `total_chapters_planned`
- 记录变更到 `history.json`

## 输出格式

分卷细纲以结构化 JSON 格式保存到 `volumes/vol-{n}.json`，同时向用户展示可读版本。

## 注意事项

- **严格对齐总大纲**：本卷只能写大纲中该卷的内容
- 每章必须有存在的理由，不能是纯过渡章
- 章末钩子要自然，不能刻意
- 场景规划要具体到冲突和转折，不能只是"他们聊了聊"
- 卷与卷之间要有阶段性收束，同时留有悬念
- 如果章节数很多（>100），可以分批规划，先规划前 30 章
- 多女主类型必须交替推进，不能一条线写到尾
